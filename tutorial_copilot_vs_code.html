Tutorial de uso do ResistoHub

Guia rápido para navegar no portal, acessar os módulos principais, publicar conteúdo e usar os recursos de bioinformática, vigilância, protocolos e comunidade.

Guia rápido para aproveitar a ferramenta dentro do editor: pedir ajuda, editar arquivos, usar o contexto ResistoHub Bioinformatics Surveillance Community VS Code GitHub Copilot Chat

1. O que esta ferramenta faz

O Copilot Chat ajuda a entender código, propor mudanças, corrigir erros, escrever documentação e executar tarefas no seu workspace com mais rapidez.

  • Explica trechos de código e arquivos inteiros.
  • Propõe correções e refatorações.
  • Ajuda a criar componentes, testes e documentação.
  • Consulta o contexto do projeto aberto no VS Code.

2. Como começar

  1. Abra o VS Code e o projeto desejado.
  2. Abra o painel do Copilot Chat.
  3. Descreva o que você quer fazer com clareza.
  4. Se possível, cite o arquivo, componente ou erro específico.
Dica: pedidos curtos funcionam melhor quando o objetivo é simples; pedidos com contexto funcionam melhor para mudanças maiores.

3. Como pedir algo de forma eficiente

Bom exemplo

"Corrija este erro em nextjs/src/pages/bioinfo.tsx e preserve a estrutura atual."

Bom exemplo

"Adicione traduções para alerts em pt-br, es-es e en-us."

Evite

  • Pedidos vagos como “arruma isso”.
  • Solicitar várias mudanças sem priorizar.
  • Esquecer de dizer em qual arquivo o problema está.

4. Fluxo recomendado de uso

  1. Explique o problema ou objetivo.
  2. Peça a alteração no arquivo correto.
  3. Revise a sugestão antes de aceitar.
  4. Rode a validação do projeto.
  5. Peça ajuste fino se houver erro residual.

5. Exemplos práticos

  • Correção: “Esse componente quebra quando a API retorna vazio. Corrija sem mudar o layout.”
  • Refatoração: “Extraia a lógica de filtros para um hook reutilizável.”
  • Tradução: “Troque textos fixos por chaves de tradução em todos os idiomas.”
  • Documentação: “Gere um tutorial curto de uso para esse recurso.”

6. Boas práticas

  • Peça mudanças pequenas e verificáveis.
  • Valide erros logo após editar.
  • Evite pedir reescritas desnecessárias.
  • Confirme os nomes de arquivos e funções.

7. Quando algo der errado

Se a sugestão não estiver boa, refine o pedido com mais contexto:

  • arquivo exato;
  • erro exibido;
  • comportamento esperado;
  • restrições importantes, como manter a API atual.
Exemplo: “O erro está em nextjs/src/pages/surveillance.tsx. Corrija sem alterar os textos já traduzidos.”

8. Resumo rápido

Use a ferramenta para descrever o objetivo, apontar o arquivo certo e revisar o resultado. Quanto mais específico for o pedido, melhor será a resposta.
